# 新设备 Windows 本地部署与端口检查

适用情况说明：新电脑已经**另外安装并授权** KQGIS Desktop、KQGIS Server，只下载了 `参赛作品提交材料_20260929` 文件夹；目标是本机展示管理员智慧大屏、组长端和地图。本文不提供公网部署方案。执行过程中不要删除提交包，先从它复制出运行目录。

> **特别说明：不能直接在提交包中双击“一键启动全部环境.cmd”。** 当前脚本固定查找项目内的 `Gis\kqgisserver-lite-20260211_150534_release\kqwebservice`，而项目提交包没有附带KQGIS Desktop/Server。新电脑已另装 KQGIS 时，请按本文分别启动 KQGIS、Django 和两个 Vue 前端。只有改造一键脚本以指向新电脑的 KQGIS 安装位置之后，才能使用该脚本。

## 1. 环境与文件检查

| 项目 | 要求或用途 | 检查方法 |
| --- | --- | --- |
| Windows | 建议 Windows 10/11 64 位，能运行已安装的 KQGIS | 正常启动 Desktop 和 Server |
| Python | 3.10 或更高，带 `py` 启动器和 `pip` | PowerShell：`py --version`、`py -m pip --version` |
| Node.js / npm | Node 20.19+ 或 22.12+；推荐 22.12+ | `node --version`、`npm.cmd --version` |
| KQGIS | Desktop、Server 和有效许可证均在新电脑可用；Server 能配置为本机 9600 端口 | 按安装方方式启动并检查 9600 |
| 磁盘 | 提交包约 10.83 GiB；复制运行目录、安装依赖时建议再留至少 15 GiB 空闲 | 在目标磁盘“属性”中检查 |
| 网络 | 首次 `pip`/`npm` 安装依赖需要能访问依赖源；离线电脑需另备对应离线包 | 安装依赖时确认没有网络错误 |

确认下载完整：`04_相关数据\原始地图数据\尼泊尔泥石流巨灾` 下应有 223 个原始文件，`04_相关数据\KQGIS地图工程\当前已发布工程` 下应有 3 个 `.kqmdx`。

建议新建一个**空的** `D:\CangQiongPj` 文件夹。地图工程尽量选择保留原电脑的绝对数据路径，使用这个位置最省事；如果没有 D 盘，可以换到其他位置，但必须在 KQGIS 中重新指定图层数据源。

从提交包复制以下内容，保持目录层级，不要把 `01_开发源代码` 或 `04_相关数据` 这两个分类目录本身当作运行根目录：


## 3. 启动并重新发布 KQGIS 地图

1. 按新电脑上 KQGIS Server 的安装方式启动它，并将服务 HTTP 端口设为 **9600**。只“安装了软件”不代表项目地图服务已存在。
2. 在 KQGIS Desktop 中打开/导入提交包 `04_相关数据\KQGIS地图工程\当前已发布工程` 里的三个文件：`jilong_base.kqmdx`、`jilong_county_atlas.kqmdx`、`jilong_port_multitemporal.kqmdx`。
3. 逐层检查数据连接。如果图层提示文件不存在，把它指向第 2 步恢复的 `D:\CangQiongPj\尼泊尔泥石流巨灾` 中相应的 `.shp`、`.tif` 等原始文件；Shapefile 的 `.dbf`、`.shx`、`.prj` 等伴随文件必须保留在同一目录。不要只复制一张 `.shp` 或一张影像预览图。
4. 使用新电脑 Server 的管理员凭据重新发布、启用并启动服务，服务名**必须精确为** `jilong_base`、`jilong_county_atlas`、`jilong_port_multitemporal`。其中 `jilong_port_multitemporal` 是大屏默认的吉隆口岸多时相影像；不能只发布一景旧的 `jilong_port_imagery`。
5. 在新电脑浏览器分别打开下列地址。三个地址都要能返回地图元数据，而不是 404、登录页或服务错误：

```text
http://127.0.0.1:9600/kqgis/rest/services/jilong_base/map/getmetadata
http://127.0.0.1:9600/kqgis/rest/services/jilong_county_atlas/map/getmetadata
http://127.0.0.1:9600/kqgis/rest/services/jilong_port_multitemporal/map/getmetadata
```

如果 Server 使用的不是 9600，建议先改为 9600；否则还要同步修改 `app\frontend\vite.config.js` 中 `/kqgis` 的代理目标。只让端口处于监听状态并不能证明地图正确，最终还需在大屏中检查口岸影像及县域专题图能实际出图。


```powershell

```

## 5. 分别启动四项服务

先确保 KQGIS Server 已在 9600 端口运行，然后在上面三个 PowerShell 窗口中分别运行以下命令，演示期间保持窗口打开：

```powershell
# 后端窗口，当前目录 D:\CangQiongPj\app\backend
py .\manage.py runserver 127.0.0.1:8000 --noreload
```

```powershell
# 管理员前端窗口，当前目录 D:\CangQiongPj\app\frontend
npm.cmd run dev
```

```powershell
# 组长前端窗口，当前目录 D:\CangQiongPj\app\team-frontend
npm.cmd run dev
```

应用端口对应关系：

| 端口 | 服务 | 本机展示时的防火墙要求 |
| --- | --- | --- |
| TCP 5173 | 管理员登录、大屏及调度后台；代理 `/api` 和 `/kqgis` | 只在这台电脑浏览器展示时，不需新增入站开放规则 |
| TCP 5174 | 组长 Web/手机端入口；代理 `/api` | 只在这台电脑浏览器展示时，不需新增入站开放规则 |
| TCP 8000 | Django API，绑定 `127.0.0.1` | 不要对外开放；由 5173/5174 代理访问 |
| TCP 9600 | KQGIS Server 地图服务 | 不要对外开放；由 5173 的 `/kqgis` 代理访问 |

本地验收地址：管理员 `http://127.0.0.1:5173/#/login`，组长端 `http://127.0.0.1:5174/`。这两个地址只能在运行服务的电脑上使用，**不是公网在线地址**。

## 6. 手机在同一局域网访问

此节只适用于手机与电脑连接同一可互通的 Wi-Fi/局域网；管理员和组长端默认监听所有网卡，手机访问时应使用电脑实际的局域网 IPv4，例如 `http://192.168.1.20:5174/`，**不能在手机上填 `127.0.0.1`**。先用 `ipconfig` 找到电脑当前的 IPv4；不要照抄示例地址。

在启动 Django 的**同一个 PowerShell 窗口**、运行 `runserver` 之前，按实际 IP 设置 CSRF 来源（将 `192.168.1.20` 换成新电脑 IP）：

```powershell
$lanIp = '192.168.1.20'
$env:DJANGO_ALLOWED_HOSTS = "127.0.0.1,localhost,$lanIp"
$env:DJANGO_CSRF_TRUSTED_ORIGINS = "http://127.0.0.1:5173,http://127.0.0.1:5174,http://localhost:5173,http://localhost:5174,http://${lanIp}:5173,http://${lanIp}:5174"
py .\manage.py runserver 127.0.0.1:8000 --noreload
```

Windows 防火墙仅需给**专用网络（Private）**上的 TCP **5173、5174 入站**放行：打开“Windows 安全中心 → 防火墙和网络保护 → 高级设置 → 入站规则 → 新建规则 → 端口”，选择 TCP 及 `5173,5174`，仅勾选“专用”。不要为了手机访问而放开 8000 或 9600，也不要设置路由器公网端口映射。电脑与手机若处于访客网络、不同网段或 Wi-Fi 开启客户端隔离，仍可能无法互通。

组长 Web 端地址是 `http://<电脑局域网IP>:5174/`。如果展示的是独立开发的手机 App，需在 App 中把服务地址设为这个 5174 地址，使其通过 `/api` 代理访问 Django；若 App 固定直接请求电脑的 8000 端口，则本方案不适用，需另行调整 App 配置与服务监听方式。手机 App 源码不在当前提交包中。

## 7. 最终验收与排错

在新电脑 PowerShell 中检查端口：

```powershell
Get-NetTCPConnection -State Listen -LocalPort 5173,5174,8000,9600 -ErrorAction SilentlyContinue |
  Select-Object LocalAddress,LocalPort,OwningProcess
```

至少应看到 5173、5174、8000、9600。接着依次验证：

1. 管理员端能以 `admin` / `123` 登录，默认大屏显示吉隆口岸影像。
2. 点击左侧资料卡能切换到吉隆县相应专题图，再点返回口岸。
3. 管理员点击地图产生标记点、分配队伍；组长端能用数据库内的组长手机号及默认密码 `123` 登录并看到任务。演示数据库初始没有测试任务，需现场创建。
4. 组长端推进阶段或上传图片后，大屏标记状态可更新。需要真实手机演示时再检查第 6 节的局域网访问。

常见问题：

- **“KQGIS launcher not found”**：误用了旧一键启动脚本；按本文分别启动，或另行改造脚本指向新电脑的 Server 安装目录。
- **页面可开但地图空白**：先检查 9600、三个精确服务名、元数据地址；再检查地图工程的原始文件路径和实际 WMS 出图。
- **左侧资料卡没有数据**：检查原始数据是否位于 `D:\CangQiongPj\尼泊尔泥石流巨灾`，并查看 Django 窗口的报错。
- **5173/5174 无法访问**：检查 `npm ci` 是否成功、三个终端是否仍在运行，以及端口是否被其他程序占用。
- **手机能打开页面但登录/提交失败**：检查是否使用电脑的局域网 IP、是否在启动 Django 前设置 `DJANGO_CSRF_TRUSTED_ORIGINS`、防火墙是否只在专用网络放行 5174。
- **管理员 `admin/123` 登录失败**：检查是否把第 04 项提供的演示 `db.sqlite3` 放进了 `app\backend`，以及是否误用了新建的空库或其他旧数据库。

本指南仅保证在依赖安装成功、地图图层正确重连并重新发布的前提下按步骤恢复本地演示；“仅下载提交包并已安装 KQGIS”本身不足以自动恢复发布服务。
