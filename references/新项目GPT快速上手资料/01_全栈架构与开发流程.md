# 全栈架构与开发流程

## 1. 推荐架构

```text
用户浏览器
  |
  |-- Vue 3：页面、组件、状态、交互
  |-- Leaflet：地图容器、WMS、GeoJSON、地图事件
  |-- ECharts：趋势图、柱状图、排名图
  |
  v
Django REST API
  |
  |-- 数据读取：CSV/Excel/GeoJSON/数据库
  |-- 业务计算：统计、筛选、派生指标
  |-- GIS 辅助：Shapefile 转 GeoJSON、服务配置
  |-- WMS 代理：仅在鉴权、跨域、缓存、透明化需要时
  |
  +--------------------------+
  |                          |
  v                          v
用户真实业务数据        KQGIS Server
CSV / Excel / DB        MapService / WMS / WMTS / WFS
                             |
                             v
                       Shapefile / GeoTIFF

KQGIS Desktop：位于运行链路之外，负责数据检查、制图预览和发布前验证。
```

## 2. 每个技术的本质

### Vue

Vue 不是一种新语言，而是基于 JavaScript 的前端框架。`.vue` 组件通常包含：

- `<template>`：HTML 页面结构。
- `<script setup>`：JavaScript 数据和交互。
- `<style>`：CSS 样式。

Vue 的核心价值是组件化和响应式更新：API 数据变化后，页面自动更新。

### Django

Django 是 Python Web 框架。建议用 Django REST Framework 返回 JSON API。它负责：

- 读取和校验真实数据。
- 把复杂文件结构转换为前端容易使用的 JSON。
- 承担业务计算，避免关键公式散落在前端。
- 隐藏 KQGIS 凭据和内部地址。
- 提供统一错误、日志和健康检查。

### KQGIS Desktop

Desktop 是桌面 GIS 工具，主要用于：

- 打开 Shapefile、GeoTIFF 等空间数据。
- 检查坐标系、范围、波段、NoData 和图层叠加。
- 设计颜色带、分级和边界样式。
- 发布前人工核对地图是否正确。

### KQGIS Server

Server 是 GIS 服务端。它读取本地 GIS 数据，根据浏览器请求动态输出地图图片或要素。Web 项目通常使用：

- WMS：按范围动态出图。
- WMTS：按固定瓦片矩阵提供地图瓦片。
- WFS：返回矢量要素和属性。

### Leaflet

Leaflet 是浏览器地图库。它不负责计算遥感数据，而是：

- 创建可缩放、可平移的地图。
- 计算当前视口的地理范围。
- 请求 WMS 图片瓦片并拼接显示。
- 绘制 GeoJSON 并处理点击、悬停和弹窗。

### ECharts

ECharts 是前端图表库。它把 Django 返回的 JSON 数据绘制成折线图、柱状图、饼图、散点图等。ECharts 不应成为业务数据来源。

## 5. 开发阶段与退出条件

### 阶段 A：环境和数据清点

工作内容：

- 检查 Python、Node、KQGIS 版本。
- 列出全部文件。
- 读取空间和表格元数据。
- 查找数据间关联键。

退出条件：`docs/数据清单.md` 完成，关键字段含义和时间范围没有被猜测。

### 阶段 B：原型和需求映射

工作内容：

- 确定页面数量和核心工作流。
- 每个 UI 区域对应真实数据源。
- 确定地图主图层、交互图层和图表。
- 定义 API 草案。

退出条件：不存在“先放假数据以后再说”的业务面板。

### 阶段 C：GIS 服务

工作内容：

- Desktop 检查数据。
- Server 发布 MapService。
- 读取元数据和图层 ID。
- 测试 WMS GetMap。

退出条件：每个计划展示的图层都有可复现的成功请求和数据来源记录。

### 阶段 D：Django API

工作内容：

- 创建数据访问和业务 service。
- 创建 JSON API、GeoJSON API 和健康检查。
- 必要时添加 KQGIS WMS 代理。
- 添加测试。

退出条件：API 独立于前端可测试，错误情况有明确状态码和信息。

### 阶段 E：Vue 页面

工作内容：

- 建立页面和组件。
- 接入 API。
- 接入 Leaflet WMS/GeoJSON。
- 接入 ECharts。
- 添加加载、空数据和错误状态。

退出条件：页面上不存在来源不明的业务数值，图层切换和数据联动可验证。

### 阶段 F：整体交付

工作内容：

- 一键启动和停止。
- 多分辨率验收。
- 离线/异常测试。
- 文档和答辩准备。

退出条件：换一个终端按照 README 可以启动；已知限制被诚实记录。

## 6. 推荐 API 设计

接口名需按业务调整，通用基线如下：

| 接口 | 用途 |
| --- | --- |
| `GET /api/health/` | 检查 Django、数据文件和 KQGIS 服务 |
| `POST /api/auth/login/` | 登录；正式项目使用 Django 用户和安全认证 |
| `GET /api/overview/` | 首页总览指标 |
| `GET /api/series/?metric=&year=` | 时间序列 |
| `GET /api/regions/?metric=&year=` | 各地区指标 |
| `GET /api/regions/<id>/trend/` | 单地区趋势 |
| `GET /api/map/boundary/` | GeoJSON 交互边界 |
| `GET /api/map/layers/` | KQGIS 服务和真实图层配置 |
| `GET /api/kqgis/wms/` | 可选的 WMS 代理 |
| `GET /api/data-sources/` | 页面展示数据来源和处理说明 |

返回结构应稳定，字段包含单位和必要元数据。例如：

```json
{
  "metric": "ndvi",
  "unit": "dimensionless",
  "year": 2025,
  "source": "NDVI_2025.tif",
  "items": []
}
```

## 7. 前端组件建议

```text
App.vue
|-- LoginView.vue
`-- DashboardView.vue
    |-- HeaderBar.vue
    |-- RegionMap.vue
    |-- LayerControl.vue
    |-- MetricPanel.vue
    |-- ChartPanel.vue
    |-- DataSourceDialog.vue
    `-- StatusBanner.vue
```

组件职责应清楚：

- `RegionMap` 只处理地图显示和地图事件。
- `ChartPanel` 只根据 props 绘图和更新。
- `DashboardView` 负责选择年份、指标、区域以及协调 API 请求。
- API URL 集中在 `services/api.js`，不要散落在各组件。
- KQGIS 服务信息由后端提供，不要把绝对路径和敏感信息放进前端。

## 8. 登录功能边界

样例项目的登录只是演示逻辑，固定账号和演示 token 不适用于正式项目。新项目应根据比赛要求选择：

- 纯演示：可以使用明确标注的本地演示账号，但不得宣称为正式安全系统。
- 正式账号：使用 Django 用户模型、密码哈希、会话或 JWT、权限控制和限流。

无论哪种方式，输入框不得自动暴露密码，前端不得保存明文密码。

## 9. 一键启动建议

启动脚本依次完成：

1. 检查端口是否已占用。
2. 启动 KQGIS Server。
3. 启动 Django。
4. 启动 Vite。
5. 轮询三个健康地址。
6. 输出每个服务的状态和日志路径。
7. 全部就绪后打开浏览器。

推荐端口：

```text
KQGIS Server  9600
Django       8000
Vite         5173
```

端口可以更换，但所有配置必须由环境变量或统一配置管理，不要在多个文件重复硬编码。

## 10. 本地开发与生产部署

### 本地开发

Vite 将 `/api` 转发到 Django。KQGIS 可以由前端直接请求，也可以由 Django 代理。

### 生产部署

不要使用 Django `runserver` 和 Vite dev server。建议：

```text
Nginx/网关
|-- /         Vue build 静态文件
|-- /api/     Django WSGI/ASGI 服务
`-- /kqgis/   KQGIS Server 或受控代理
```

生产前至少处理：

- `DEBUG=False`
- 限定 `ALLOWED_HOSTS`
- `SECRET_KEY` 环境变量
- HTTPS
- 数据和服务访问权限
- 日志轮转
- 静态资源构建
- 数据备份
- CORS/CSRF 策略

## 11. 测试策略

### 后端

- 数据文件缺失时的错误。
- 年份/指标参数校验。
- 数据筛选和派生公式。
- GeoJSON 几何与属性数量。
- KQGIS 在线、离线、超时和错误响应。

### 前端

- 登录、退出和错误提示。
- API 加载、空数据、失败状态。
- 图层切换、年份切换、区域选择。
- ECharts 更新而不重复初始化。
- 页面尺寸变化后的地图 `invalidateSize` 和图表 resize。

### GIS

- 元数据中的 EPSG、范围和图层数。
- 每个图层的 GetMap。
- NoData、透明背景和边界对齐。
- Server 重启后服务自动恢复。

## 12. 不能机械复制的样例实现

以下内容必须在新项目重新确认：

- 数据目录和文件名。
- 地图中心、范围和缩放级别。
- EPSG。
- KQGIS 图层 ID。
- 指标公式和单位。
- 登录方式。
- 服务名和端口。
- 多波段 TIF 的年份含义。
- NoData 透明阈值。
