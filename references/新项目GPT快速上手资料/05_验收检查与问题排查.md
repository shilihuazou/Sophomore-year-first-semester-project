# 验收检查与问题排查

## 1. 总体排查原则

地图不显示时不要同时修改所有层。始终从底向上排查：

```text
文件
-> KQGIS Server 进程
-> 具体地图服务
-> 元数据
-> WMS GetMap
-> Django 代理
-> Vue/Leaflet
-> 页面遮挡和样式
```

图表不正确时按以下顺序：

```text
原始表格
-> 清洗/关联
-> Django service 计算
-> API JSON
-> Vue 状态
-> ECharts option
```

## 4. KQGIS Server 验收

### 进程层

```powershell
Get-NetTCPConnection -LocalPort 9600 -State Listen
Invoke-WebRequest `
  -Uri 'http://127.0.0.1:9600/kqgis/server-manager/services/version' `
  -UseBasicParsing
```

- [ ] 端口监听。
- [ ] 版本接口返回 HTTP 成功。

### 服务层

```text
http://127.0.0.1:9600/kqgis/manager/queryserviceinfo?servicename=<SERVICE>
http://127.0.0.1:9600/kqgis/rest/services/<SERVICE>/map/getmetadata
```

- [ ] 服务存在。
- [ ] 服务已启用。
- [ ] 自动启动已开启。
- [ ] 元数据范围、EPSG 和图层数正确。
- [ ] 图层 ID 已记录，而非猜测。

### WMS 层

测试请求必须包含：

```text
SERVICE=WMS
VERSION=1.1.1
REQUEST=GetMap
LAYERS=<真实图层ID>
FORMAT=image/png
TRANSPARENT=TRUE
SRS=<真实EPSG>
BBOX=<真实范围内的小范围>
WIDTH=800
HEIGHT=600
```

- [ ] HTTP 200。
- [ ] `Content-Type: image/png`。
- [ ] 图片不是错误页、全空白或错误位置。
- [ ] 每个业务图层分别测试。
- [ ] 重启 Server 后再次测试。

## 8. 常见问题

### 9600 无法访问

检查：

1. KQGIS 启动窗口是否报环境变量或数据目录错误。
2. `KQMS_DATA_PATH` 是否指向真实目录。
3. 端口是否被其他进程占用。
4. Server 日志中的第一个错误，而不是只看最后一行。

### 服务列表看不到动态发布的数据

“数据目录”和“地图服务”是不同概念。`Folder` 数据源动态创建的服务可能不出现在数据分类中。应查询服务列表、`queryserviceinfo` 和 `getmetadata`。

### `queryserviceinfo` 有服务，但 REST 提示资源不存在

可能是 Lite 版服务实例和管理资源/权限目录没有同步。优先：

1. 使用已登录的管理界面重新启用或发布。
2. 检查服务归属和匿名访问权限。
3. 保存管理日志和服务创建日志。
4. 重启后复查。

不得直接照搬旧项目的内部 SQLite 记录。确需研究数据库时先完整备份并征得用户确认。

### WMS 全黑或外部黑框

1. 在 Desktop 检查 TIF 的 NoData。
2. 确认 Server 是否输出 Alpha。
3. 优先修复数据或服务样式。
4. 最后才使用 Django 像素透明化。

不能把所有黑色都删掉，黑色可能是有效像元。

### WMS 空白

检查：

- 图层 ID 是否来自新服务元数据。
- BBOX 是否落在服务范围内。
- EPSG 是否一致。
- WMS 1.1.1 使用 `SRS`；若改用 1.3.0，要注意 `CRS` 和轴顺序。
- 图层是否受比例尺范围限制。
- Server 是否有读取源文件权限。

### 地图错位

- 比较源数据 CRS、服务 CRS、WMS 请求 CRS 和 Leaflet CRS。
- 不要把 EPSG:4490、4326、3857 当成完全相同。
- 检查经纬度是否交换。
- 用 Desktop 同时加载图层作为基准。

### 年份滑块改变数字但影像不变

说明前端只切换了统计 API，没有切换 WMS 波段/图层。需要拆分逐年 TIF、逐年图层，或验证 KQGIS 的时间/波段参数。

### Django 代理能访问，前端仍不显示

- 检查代理的 `Content-Type`。
- 检查前端 WMS URL 是否指向代理。
- 检查查询参数是否原样转发。
- 检查 Vite/Nginx 是否错误缓存或重写 URL。
- 检查地图容器高度和图层 pane/z-index。

### 图表数据与地图不一致

- 核对 metric、year、region 三个筛选状态。
- 比较 API 响应与组件 props。
- 核对单位和归一化。
- 检查地区名称关联失败。

## 10. 完成定义

项目只有同时满足以下条件才算完成：

1. 真实数据链路可追溯。
2. KQGIS 服务重启后仍可用。
3. Django 接口经过测试。
4. Vue 构建成功并完成关键交互。
5. 页面异常状态完整。
6. 一键启动可复现。
7. 文档与实际代码、服务和图层 ID 一致。
8. 已知限制没有被隐藏。
