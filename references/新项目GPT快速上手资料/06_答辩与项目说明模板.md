## 3. 各技术的答辩解释

### Vue

```text
Vue 是基于 JavaScript 的前端框架，不是一门独立语言。本项目用 Vue 将页面拆成地图、图表、指标面板和图层控制等组件，并通过响应式状态实现年份、指标和区域选择后的联动更新。
```

### Django

```text
Django 是 Python Web 框架。本项目用它读取和校验真实数据、执行统计或派生计算，并通过 REST API 向前端提供 JSON/GeoJSON。必要时 Django 还作为 KQGIS WMS 的代理，但它本身不是地图渲染引擎。
```

### KQGIS Desktop

```text
KQGIS Desktop 用于发布前的数据检查和制图验证，包括坐标系、空间范围、波段、NoData、叠加位置和显示样式。它不需要在浏览器运行时一直打开。
```

### KQGIS Server

```text
KQGIS Server 读取本地 Shapefile/GeoTIFF，并发布 MapService。浏览器发送包含图层、坐标系、范围和图片尺寸的 WMS GetMap 请求，Server 动态渲染 PNG 返回。这是项目使用主办方 GIS 平台完成 Web 二次开发的核心。
```

### Leaflet

```text
Leaflet 是浏览器地图库。它把当前地图视口拆成多个小块，计算每块的地理 BBOX，向 KQGIS WMS 请求 PNG，再拼接成可缩放地图。GeoJSON 点击和高亮也由 Leaflet 负责。
```

### ECharts

```text
ECharts 负责把 Django 返回的真实 JSON 数据绘制成趋势、对比或排名图。它只做可视化，不生成业务数据。
```

## 7. 常见问题与回答

### 为什么既用 Desktop 又用 Server？

Desktop 负责人工检查和制图，Server 负责把地图能力变成浏览器可访问的网络服务。两者是制作/验证与运行/发布的分工。

### Server 发布的具体是什么？

发布的是 MapService 及 WMS 等接口。源数据仍是本地 GIS 文件，Server 根据请求动态渲染地图图片。

### 浏览器看到的是 PNG，为什么还能点击区域？

PNG WMS 负责影像显示。点击通常由叠加的 GeoJSON/WFS 矢量层处理，或通过 WMS GetFeatureInfo 查询，不是 PNG 自己包含可点击属性。

### 为什么要经过 Django？

业务 JSON 必须由 Django 提供。WMS 是否经过 Django取决于鉴权、跨域、缓存或 NoData 处理需求；能直接访问时不必多一次中转。

### 数据是不是实时的？

按真实情况回答：如果数据是历史年度文件，就明确说是历史数据展示；只有接入持续更新的数据源和更新机制后才能称为实时。

### 年份滑块是否切换了遥感影像？

必须按实际实现回答。若只切换统计 API，就说只改变了统计数据；只有 WMS 图层、波段或时间参数也切换并经过验证时，才说影像同步切换。

### 为什么不用第三方在线地图直接展示？

本项目重点是基于 KQGIS 的 GIS 二次开发。KQGIS Server 发布用户真实专题数据，Leaflet 负责 Web 展示。第三方底图若使用，只是空间参考背景，并非核心业务数据。

### 如何保证数据准确？

回答应包括：数据来源登记、原始文件只读、CRS/范围/字段检查、处理记录、公式公开、接口测试、地图服务逐层 GetMap 验证以及页面数据来源说明。

### 系统的创新点是什么？

只从真实实现中选择，例如：

- KQGIS 服务与 Web 大屏集成。
- 遥感栅格、行政区矢量和统计表格的多源联动。
- 可追溯数据来源和派生指标说明。
- 一键启动与服务健康检查。

不要把常规登录、普通折线图或尚未实现的 AI 预测包装成创新。
