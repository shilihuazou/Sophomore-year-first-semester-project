# Vue + Django + KQGIS 新项目 GPT 快速上手资料包

## 这个资料包的用途

把整个文件夹复制到新项目根目录，并将 `00_新项目GPT总提示词.md` 的内容作为新 Codex/GPT 对话的第一条任务说明。新项目还应同时提供：

- 主办方提供的 KQGIS Desktop 与 KQGIS Server 安装包或解压目录。
- 用户提供的真实 GeoTIFF、Shapefile、CSV、Excel、GeoJSON 等数据。
- 项目要求、界面参考图、比赛规则和已有文档。
- 允许使用的账号、端口与部署环境，但不要把密码写进代码仓库。

本资料包不包含新项目的业务数据，也不会替新项目预设地图范围、统计值、图层编号或指标结论。

## 推荐阅读顺序

1. `00_新项目GPT总提示词.md`

## 资料依据

本资料包依据已经完成的“基于 KQGIS 的洪水监测系统”整理。该样例项目使用：

```text
Vue 3 + Vite
Django + Django REST Framework
Leaflet
ECharts
KQGIS Desktop 8.5
KQGIS Server Lite 8.5
```

样例项目完成了 Shapefile 边界和 GeoTIFF 遥感栅格的 KQGIS MapService/WMS 发布、Django 数据接口与 WMS 代理、Vue 智慧大屏、Leaflet 地图和 ECharts 图表。

版本号只是样例事实，不是新项目必须照抄的依赖。新 GPT 必须先读取新项目实际软件版本和数据。

## 三条最高优先级规则

1. **不编造数据。** 页面中的地图、数值、年份、范围、排名和结论必须能追溯到用户文件或有明确依据的计算。
2. **不假装验证。** 没有实际打开文件、请求接口或运行测试，就必须写“尚未验证”。
3. **不破坏原始资料。** 原始 GIS 数据只读保存；重投影、裁剪、修复和派生结果写入单独的 `processed` 目录并记录过程。

## 使用方式

新对话推荐这样开始：

```text
请先完整阅读“新项目GPT快速上手资料”文件夹，严格遵守其中的数据真实性和操作限制。然后只做第一阶段：清点整个项目、识别软件版本、读取所有数据元信息，并生成数据清单与待确认问题。未完成数据核验前不要编写虚构的页面数据，也不要发布地图服务。
```
